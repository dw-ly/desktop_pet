> 关联 Spec：[[7-AI学习/11-AI桌宠情侣互联/spec/pet-growth/spec.md|spec/pet-growth]]
> 创建日期：2026-08-03
> 状态：已完成（G1/S1-S5/C1/C2 全部落地，59 单测 + 联调绿）

## 1. 技术方案概述

共同养成是 M3 核心模块：两人共同养一只团子，互动产生亲密度与经验，解锁装扮与动作。核心链路：本地互动行为 → 计算积分增量（delta/reason）→ 会话密钥派生 MAC 子密钥签名 → `pet.feed` 加密同步 → 接收端校验签名 + 每日上限后经 `apply_intimacy_event` 合入 → 两端从事件流重放收敛 → 每日零点结算连续登录与灰色期状态机 → `date.sync` 对齐。宠物名通过 `pet.profile` 同步到对方 `pairing.peer_pet_name`；形象以素材包 manifest 加载（3 款预设），不硬编码。

本模块**不重复实现** data-consistency 已有的能力（`pet_state` 表读写、`apply_intimacy_event` 合入、`date.sync` 对齐、签名密钥派生），只做积分的业务计算与养成逻辑。纪念日加成通过**可注入判定钩子**解耦：anniversary 模块落地前钩子返回"非纪念日"（无加成），落地后自动生效，不阻塞本模块。

## 2. 技术决策

### 2.1 方案选型

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 状态存储 | `pet_state` 表（key-value：level/exp/intimacy/streak_days/grace 等），本端一份 | spec 已定；data-consistency 已建表 |
| 积分增量同步 | `pet.feed` 事件，负载含 delta / reason / ts / sig | spec 已定；事件流重放收敛 |
| 签名 | 会话密钥 HKDF 派生独立 MAC 子密钥（HMAC），与 data-consistency 同一派生函数 | 防篡改 + 密钥分离；两端一致校验 |
| 合入校验 | 复用 data-consistency `apply_intimacy_event`（签名校验 + 每日 reason 上限） | 不重复实现；重大异常停止自动合入逻辑已含 |
| 等级曲线 | 经验 = k·等级²（初始 k = 100，即 level = int(sqrt(exp/100))），前期快后期慢 | spec 决议；04 号笔记公式一致（k=100） |
| 等级解锁里程碑 | **5 / 10 / 15 级**（解锁动作/装扮），配置表驱动 | spec 决议；04 号笔记 L2/L5/L8/L12 为早期清单，以 spec 为准统一（见风险） |
| 亲密度里程碑 | 100 爱心气泡 / 365 纪念日套装 / 1000 羁绊徽章（初始值） | 04 号笔记初始值；spec 仅定义"到达里程碑"，M3 内测后调优 |
| 纪念日加成 | 积分计算调用**可注入钩子** `is_anniversary_today()`；anniversary 未就绪时返回 False | 解耦开发顺序：pet-growth 先于 anniversary，不阻塞 |
| 每日结算 | 每日零点定时任务：streak 结算 + 灰色期状态机 + `date.sync` 对齐；断网推迟 | spec 已定；复用 data-consistency daily_sync 时机 |
| 宠物名同步 | `pet.profile`：配对成功后发送 + 本端改名重发；对方存 `pairing.peer_pet_name` | spec 已定 |
| 形象选择 | 素材包 manifest 加载（`assets/pets/<id>/manifest.json`），程序不硬编码；首批 3 款（月薪猫、线条小狗 ×2） | spec 已定；08 美术资源规划排期 |
| 解锁映射 | 等级/亲密度里程碑 → 解锁物品 id 的配置表（含 04 号笔记物品池：动作/装扮/动画/彩蛋位） | 配置化便于内测调优，不写死逻辑 |

### 2.2 外部依赖

| 依赖 | 用途 | 新增 |
|------|------|:---:|
| data-consistency（db / consistency / daily_sync） | `pet_state` 表、`apply_intimacy_event`、`date.sync` 对齐 | 复用（本模块首个业务消费者） |
| 同步层 | `pet.feed` / `pet.profile` 事件发送与接收、连接状态 | 复用 |
| 主项目动画状态机 | 解锁动作/装扮的展示 | 复用 |
| 主项目"宠物名输入 + 形象选择"能力 | 名字输入与预设形象选择入口 | **待主项目补充**（当前主项目为固定角色"团子"） |
| 08 美术资源规划 | 解锁装扮视觉资源排期、形象素材包 | 复用 |
| — | 新增第三方库 | 无 |

### 2.3 内部依赖

- **事件注册表**：`pet.feed` / `pet.profile` 已在 sync-security 登记，本模块消费。
- **data-consistency**：`apply_intimacy_event`（签名校验 + 每日上限 + 重放）为亲密度合入唯一入口；`pet_state` 表读写封装；`date.sync` 对齐与每日零点定时。
- **纪念日钩子**：`is_anniversary_today()` 由 anniversary 模块实现并注册；未注册默认 False。
- **配置**：等级曲线 k、等级/亲密度里程碑、灰色期参数（3 天）、各 reason 每日上限、积分来源表（唯一基准，spec §3.3.2）。
- **形象素材包**：`assets/pets/<id>/manifest.json` 清单结构（id、名称、各状态素材路径），按 08 号笔记约定。

## 5. 测试标准

### 5.1 单元测试标准

- **积分计算**：各 reason 数值与触发条件；每日上限边界（恰好达到 / 超出）；带话 5min 频率限制；纪念日加成（×2 取整、礼物 +20 不叠加）。
- **等级曲线**：exp 换算边界；里程碑 5/10/15 解锁；亲密度 100/365/1000 解锁；只增不降。
- **灰色期状态机**：正常态有活动 +1；漏登转灰（灰色计数 3）；灰色期有活动 streak 照常 +1 且恢复日累计；连续 3 日恢复 normal；灰色期漏登 -1 且恢复日清零；耗尽 streak 清零。
- **积分同步**：双端重放一致；签名非法丢弃；超上限拒绝；离线补发不重复。
- **宠物名**：配对发送 / 改名重发 / 对方状态栏显示；形象清单加载与缺失兜底。

### 5.2 集成 / 场景验证标准

- **前置条件**：sync-security、data-consistency 联调通过，双端配对在线。
- **步骤**：A 喂食摸头 → B 收到积分 → 双方亲密度一致 → A 连续触发同 reason 超上限 → 被拒不计 → 构造伪造签名事件 → 被丢弃 → 批量经验 → 升级解锁弹窗 → 每日零点 → 连续登录 +1 → 模拟漏登 → 转灰色期 → 恢复 3 日 → 回正常 → A 改宠物名 → B 状态栏同步 → 形象切换生效。
- **期望结果**：积分同步、防作弊、升级解锁、灰色期、改名全链路正确，两端状态收敛一致。
- **异常场景**：超上限、签名非法、离线补发、断网时结算推迟、形象素材缺失兜底。

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 纪念日加成依赖 anniversary 模块未就绪 | 纪念日当天无加成 | 可注入钩子 `is_anniversary_today()`，未注册默认 False；anniversary 落地后自动生效 |
| 等级解锁里程碑 spec（5/10/15）与 04 号笔记（L2/L5/L8/L12）不一致 | 解锁节奏混乱 | 以 spec 决议 5/10/15 为准、配置表驱动；04 号笔记为早期清单（含动作/装扮/动画/彩蛋位物品池），建议审阅后同步修订 04 号笔记 |
| 主项目"宠物名输入 + 形象选择"能力未补充 | 改名/选形象入口缺失 | 先用配置占位与 manifest 预置 3 款，能力补充后接入 UI；逻辑先行 |
| 双方共谋刷积分 | 亲密度虚高 | 每日上限 + 签名双重约束，尽力而为（spec 已接受边界） |
| 形象素材缺失 | 形象加载失败 | manifest 缺失项兜底默认形象；08 号笔记排期 M3 内测前替换本体 |
| 每日结算与对齐依赖连接 | 断网时结算延后 | 断网推迟到重连后补齐；以双方均有活动的天数为准 |
| 等级/亲密度只增不降与事件回退冲突 | 状态回退 | 事件流只重放不覆盖；一次性/增长类以 accept 与事件为准（data-consistency 已定） |

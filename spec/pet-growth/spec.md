# 共同养成（一起养团子）需求规格说明

> 状态：已确认
> 创建日期：2026-08-03
> 所属里程碑：M3

## 1. 概述

### 1.1 功能简述
两人共同养一只团子：互动越多，团子经验与亲密度越高，解锁更多装扮与动作。团子状态在两端保持一致。给关系一个"共同的进度条"，制造持续互动的理由。

### 1.2 所属模块
`core/pet_growth.py`（状态、积分、成长、宠物档案）、同步层事件 `pet.feed` / `pet.profile`、`06-数据模型` 中 `pet_state` 表与 `pairing.peer_pet_name` 字段。

## 2. 用户故事与场景

### 2.1 目标用户
已配对的情侣双方。价值在于"共同拥有物"的仪式感与持续互动的理由。

### 2.2 用户故事
- 作为用户，我希望和 TA 一起养团子能看到共同的成长，以便有"一起做一件事"的感觉。
- 作为用户，我希望我的每一次互动都有意义（积分、解锁），以便愿意长期使用。
- 作为用户，我希望任何一方刷积分都被阻止，以便公平。

### 2.3 使用场景
1. **共同成长**：两人连续一周每天互动，团子升到 5 级解锁一套装扮。
2. **纪念日加成**：纪念日当天两人互动，亲密度获得双倍积分，解锁情侣装扮。
3. **防刷分**：一方尝试反复带话刷积分，被每日上限限制，亲密度不虚增。

## 3. 功能需求

### 3.1 输入
- 各类互动行为事件（带话送达、共同对话、纪念日互动、日常喂食/摸头、共同登录）。
- 用户操作：喂食、摸头等本地交互；修改本端宠物名（名字由用户输入、形象从内置预设中选择，能力由主项目提供）。

### 3.2 输出
- 团子状态（等级、经验、亲密度、连续登录天数、已解锁列表）。
- 升级/解锁提示、亲密度变化提示。

### 3.3 核心行为描述
1. **状态维护**：本端维护团子的等级、经验、亲密度、连续共同登录天数与已解锁列表。
2. **积分规则（唯一来源表）**：互动积分以本表为唯一基准，其他模块（带话/礼物/纪念日）的积分说明均引用本表，不另行定义数值。

**积分来源表：**

| 行为 | 基础积分 | 触发条件 | 防滥用 |
|------|:----:|------|--------|
| 带话送达 | +10 | msg.carry 成功送达 | 双方各计一次；每带话限 1 次/5min |
| 共同对话（当日首次） | +5 | 双方 24h 内均有对话 | 每日上限 1 次 |
| 日常喂食/摸头 | +3 | 本地交互 | 每日上限 5 次 |
| 礼物接受 | +5 | gift.accept 到达 | 双方各计一次；以接受事件为准 |
| 连续共同登录 | +streak×2 | 双方均在线 | 以自然日计；中断进入灰色期（见下） |

**纪念日加成（统一规则）**：纪念日当天，除"礼物接受"外的所有基础积分一律 ×2（取整）；"礼物接受"当天按特惠 +20 计，不与 ×2 叠加。纪念日加成每年同日限一次。

**共同登录灰色期（连续登录容错）**：连续共同登录采用"正常 / 灰色"两态判定，每日零点结算：
- 正常态下，双方均有活动则连续共同登录天数 +1、积分按 streak×2；某日任一方无活动，不立即清零，转为"共同登录灰色期"，灰色计数 = 3 天。
- 灰色期内每日照常判定：共同登录日 streak 照常 +1、积分照常按 streak×2，并累计"连续恢复日"；达成连续 3 个共同登录日即恢复为正常态，视同未中断，继续累计。
- 灰色期内任一日漏登：灰色计数 -1 且"连续恢复日"清零；灰色计数耗尽（0）则连续共同登录天数清零，重新从 0 累计。
- 灰色期在界面以灰色标签展示，streak 数值照常显示。

3. **增量同步与防作弊**：每次积分增量作为带签名的事件（签名密钥由会话密钥派生，仅双方可知）加密同步；接收端校验签名、检查当日上限后合入。
4. **等级与成长**：等级由经验值按平滑曲线换算（**初始曲线：经验 = k·等级²，前期快、后期慢**；到达特定等级解锁对应动作/装扮，**初始里程碑 5/10/15 级**，内测后按反馈调优）；亲密度到达里程碑解锁情侣专属装扮与徽章；连续共同登录天数递增，中断进入灰色期容错，不直接清零（见第 2 条后"共同登录灰色期"）。
5. **每日结算**：每日零点两端各自结算连续登录与重置每日计数；结算同时执行"共同登录灰色期"状态机判定（正常态 +1 / 漏登转灰或灰计数 -1 / 连续 3 个共同登录日恢复）；通过一次对齐事件校准"共同登录天数"，以双方均有活动的天数为准。
6. **一致性**：两端不从"亲密度数字"同步，而是从事件流重放收敛；每日兜底全量核对。
7. **宠物档案与名称同步**：宠物名为用户自定义输入，形象从内置预设形象中选择（**首批预设共 3 款：月薪猫、线条小狗·款一、线条小狗·款二**，不提供自由定制），配置能力由主项目提供。配对成功后本端把自己的宠物名通过 `pet.profile` 加密同步给对方，对方存于 `pairing.peer_pet_name` 并用于状态栏显示"TA 的团子：××"；本端改名后重新发送同步。形象配置不跨端传输。
8. **形象管理与替换预留**：预设形象以**素材包**形式管理——每个形象含一份清单（id、名称、各状态动画/表情素材路径），程序按清单加载，不硬编码形象。新增、替换或移除形象仅需更换/增删素材包，不改动程序逻辑。个人使用阶段直接采用网络热门表情形象（月薪猫、线条小狗），不要求授权；未来若商业化，仅需替换为授权/自绘素材包即可完成形象切换。

### 3.4 业务规则与约束
- 每个积分事件必须携带有效签名，否则丢弃并告警。
- 每个积分原因每日有上限，超限不计。
- 等级、亲密度、解锁均为只增不降（回退不产生）。
- 宠物名修改后须重新同步；形象配置仅本端生效，不同步。
- 纪念日当天基础积分 ×2，礼物接受按 +20 特惠（见上文积分来源表）。
- 连续共同登录有 3 天灰色期容错：中断不立即清零，灰色期内可恢复（见 3.3 积分来源表后"共同登录灰色期"）。
- 换机重装后，养成数据可通过对方导出或密文备份恢复。

## 4. 非功能需求

### 4.1 性能要求
- 积分事件为低频轻量消息，网络开销可忽略。
- 状态计算与本地存储操作 < 10ms。

### 4.2 安全要求
- 积分事件加密传输；签名校验失败即拒绝合入。
- 无离线可无限刷分的漏洞（每日上限 + 签名双重约束）。

### 4.3 兼容性要求
- 养成状态持久化于 SQLite，与 06 号数据模型一致。
- 两端版本一致时状态收敛；不一致时以事件流对齐。

## 5. 边界与限制

### 5.1 明确包含（In Scope）
- 团子状态维护与持久化。
- 积分规则、每日上限、纪念日加成。
- 增量事件签名与防作弊校验。
- 等级/亲密度/连续登录的成长与解锁。
- 每日结算与对齐。
- 连续共同登录的灰色期容错（中断 3 天内可恢复）。
- 宠物名同步（配对交换 + 改名重发）。
- 内置预设形象选择与素材包化管理（月薪猫 + 线条小狗 ×2，共 3 款）。

### 5.2 明确排除（Out of Scope）
- 真实付费/商城体系（装扮仅由成长解锁）。
- 团子外观美术资源的生产（仅规划解锁逻辑）。
- 复杂排行榜或社交对比。

### 5.3 已知约束
- 防作弊是"尽力而为"：每日上限 + 签名可防脚本刷分，但不能阻止双方共谋的合理互动。
- 一致性为最终一致（秒级短时不一致可接受），靠每日对齐兜底。
- 依赖主项目提供宠物名输入与内置预设形象选择能力（当前主项目为固定角色"团子"，该能力需在主项目补充；个人使用阶段美术直接采用网络表情形象，无需授权）。

## 6. 验收标准（Acceptance Criteria）

- **Given** 双方已配对；**When** A 的一条带话送达；**Then** 双方亲密度各计一次积分且频率受限。
- **Given** 一方尝试超上限刷积分；**When** 触发同一原因积分；**Then** 超出上限的增量被拒绝且不计入亲密度。
- **Given** 双方已配对；**When** 一方伪造或篡改积分事件；**Then** 签名校验失败，事件被丢弃并提示。
- **Given** 团子经验达到等级门槛；**When** 结算升级；**Then** 解锁对应动作/装扮并提示双方。
- **Given** 今天是纪念日；**When** 双方互动；**Then** 亲密度获得双倍积分。
- **Given** 双方断网后各自产生积分；**When** 恢复联网并对齐；**Then** 两端从事件流重放后亲密度一致。
- **Given** A 与 B 已完成配对；**When** A 修改本端宠物名；**Then** B 端状态栏同步显示新的宠物名。

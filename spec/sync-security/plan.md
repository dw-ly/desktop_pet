# 同步层与端到端加密 实施计划

> 关联 Spec：[[7-AI学习/11-AI桌宠情侣互联/spec/sync-security/spec.md|spec/sync-security]]
> 创建日期：2026-08-03
> 状态：已确认

## 1. 技术方案概述

在项目目录约定（`src/sync/`）下从零搭建情侣互联的**传输底座**。技术栈：Python 3.11 + PyNaCl（X25519 + XSalsa20-Poly1305）+ websockets + zeroconf + keyring。按五层职责拆分：`pairing`（配对与密钥交换）、`crypto`（加密封装）、`protocol`（协议编解码与事件类型）、`transport`（局域网直连 mDNS + WebSocket，预留中继接口）、`queue`（离线队列与去重）。

同步模块运行在**独立线程**，通过回调向 Core/UI 层暴露"事件到达"与"连接状态变化"，不直接触 UI；未配对状态禁止任何网络外发。M2 达成目标：两台同网设备配对成功、事件加密可达、离线不丢、断线重连后按序补发。

## 2. 技术决策

### 2.1 方案选型

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 非对称加密 | X25519（PyNaCl `nacl.public`） | spec 已定；libsodium 兼容，跨语言可互通（为手机端预留） |
| 对称加密 | XSalsa20-Poly1305（`nacl.secret.SecretBox`） | spec 已定；认证加密防篡改 |
| 会话密钥派生 | 共享密钥 → **HKDF-SHA256** 分离双向密钥（info 区分 A→B / B→A） | 双向独立密钥、防方向混淆；PyNaCl 提供 `crypto_kdf` 能力 |
| 配对码形式 | **12 位短码**（去易混淆字符集，内含一次性随机数） | 用户决议；无二维码依赖，输入/复制即可 |
| 密钥存储 | **keyring 库**（跨平台 DPAPI / SecretService），兜底受限权限文件（0600） | 用户决议；一条 API 覆盖多平台 |
| 局域网传输 | **双端互为 WS 服务器 + 客户端**：mDNS 广播固定服务名，发现后互相连接建双向通道 | 无"谁主动"歧义，任一端口变都自动恢复 |
| 心跳与离线 | 心跳 30s，连续 3 次无响应判定离线 → 重连退避 | spec 已定；网络抖动由退避与阈值吸收 |
| 中继 | 定义 `Transport` 抽象接口；局域网直连为 M2 实现，中继实现 M3 填充 | spec §5.1 预留接口，M2 不启用 |
| 队列持久化 | sync 模块自带 SQLite 队列表（M2 独立 schema）；data-consistency 阶段统一并入 events 表并纳入版本迁移 | 避免 sync-security 被 data-consistency（开发顺序靠后）阻塞 |

### 2.2 外部依赖

| 依赖 | 用途 | 新增 |
|------|------|:---:|
| `pynacl` | 加解密 / 密钥派生 | 已有 |
| `websockets` | WebSocket 传输 | 已有 |
| `zeroconf` | mDNS 局域网发现 | 已有 |
| `keyring` | 密钥加密落盘（DPAPI / SecretService） | **本次新增** |
| — | 二维码相关库（qrcode 等） | **不引入**（短码优先） |

### 2.3 内部依赖

- **主项目**：配置加载方式（`config.yaml`）、日志约定、异常体系；`src/sync/` 目录为新增模块。
- **数据层**：`events` 表 schema 由 data-consistency 定义，queue 在 M2 先用自带 schema，后续对齐。
- **事件注册表**：[[7-AI学习/11-AI桌宠情侣互联/spec/sync-security/spec.md|spec §3.3 事件类型注册表]] 是唯一登记处，`msg.carry` / `mood.sync` 等上层类型已登记，本 plan 只做类型常量落地。
- **UI 层**：配对对话框与状态条（本模块的 C 层 TODO），后续模块复用。

## 5. 测试标准

### 5.1 单元测试标准

- **crypto**：加解密往返；篡改密文失败；双向密钥不一致；公钥跨进程序列化稳定。
- **pairing**：握手成功；错误验证码 / 超时 / 超次 / 重复消费各失败路径。
- **protocol**：两类信封编解码往返；序号单调递增且重启不回退；去重键唯一；版本不兼容拒绝。
- **queue**：入队 / 按序补发 / 过期标记 / 重复投递去重。
- **transport**：mDNS 发现、心跳超时判定、状态机迁移、重连退避。
- **key_store**：保存 / 读取 / 删除；keyring 失败时文件兜底且权限受限。

### 5.2 集成 / 场景验证标准

- **前置条件**：两台同网 Windows 机器（或同机双实例、不同 data_dir），环境按 [[7-AI学习/11-AI桌宠情侣互联/环境准备.md|环境准备]] 就绪。
- **步骤**：启动双端 → A 生成短码 → B 输入 → 显示"已连接" → A 发一条测试事件 → B 收到并回 ack → 拔网线 → 事件入队 → 恢复网络 → 自动补发且不重复 → 任一方吊销配对 → 双方清除。
- **期望结果**：全链路通过，事件内容在抓包中仅见密文。
- **异常场景**：错误短码、配对超时、单方离线、重复投递、协议版本不兼容。

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| mDNS 在企业/校园网络被隔离 | 双端无法互相发现 | 提供手动 `IP:端口` 连接兜底 |
| Windows 防火墙拦截 WS 端口 | 直连失败 | 文档说明放行 Python 专用网络；允许自定义端口 |
| keyring 后端缺失（无桌面环境等） | 密钥无法加密落盘 | 降级受限权限文件（0600）并提示 |
| 心跳误判离线（网络抖动） | 频繁重连、事件延迟 | 重试退避递增；心跳/阈值可配置 |
| DPAPI 密钥跨机不可解密 | 换机后配对失效 | 文档说明重新配对（环境准备 §9 已覆盖） |
| queue 自带 schema 与 data-consistency 后续冲突 | 迁移成本 | M2 明确接口边界，data-consistency 阶段统一并入 events 表并版本迁移 |
| 同机双实例联调时 mDNS 服务名冲突 | 两个实例互相发现混乱 | 服务名含实例标识（由 data_dir 派生）；C2 脚本为双实例分配不同服务名 |

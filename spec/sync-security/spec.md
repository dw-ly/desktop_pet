# 同步层与端到端加密 需求规格说明

> 状态：已确认
> 创建日期：2026-08-03
> 所属里程碑：M2（基础设施，先于其他功能模块）

## 1. 概述

### 1.1 功能简述
为情侣双端桌宠提供安全的消息传输基础设施：配对与密钥交换、端到端加密、消息协议、传输通道（局域网直连优先，中继可选）。上层所有功能（带话/情绪/养成/纪念日/互赠）均复用本层。

### 1.2 所属模块
`sync/` 模块：配对（pairing）、加密（crypto）、协议（protocol）、传输（transport）、离线队列（queue）。

## 2. 用户故事与场景

### 2.1 目标用户
- 主用户：已配对的情侣双方，各自在 PC 上运行桌宠。
- 次要用户：自托管中继的部署者（M3 阶段）。

### 2.2 用户故事
- 作为用户，我希望只需输入/复制配对码即可与伴侣建立连接，以便无需专业知识就能完成加密配对。
- 作为用户，我希望断网/关机后消息不丢失，以便恢复后仍能收到。
- 作为用户，我希望他人（包括中继服务方）无法看到我的内容，以便隐私有保障。

### 2.3 使用场景
1. **首次连接**：A 点击"添加伴侣"生成配对码，B 输入配对码，双方完成握手，显示"已连接"。
2. **局域网即时通**：双方在同一 WiFi，在线状态实时显示，消息秒级送达。
3. **离线补收**：B 关机时 A 发送事件；B 上线后自动收到积压事件，且事件不重复。

## 3. 功能需求

### 3.1 输入
- 用户操作：添加伴侣、输入/复制配对码、确认配对、解除配对（吊销）、手动切换连接模式。
- 系统输入：本机身份密钥对、伴侣公钥、各类事件负载（文本、情绪标签、养成增量、纪念日、礼物、宠物名）。

### 3.2 输出
- 配对状态（未配对/已配对）。
- 连接状态（disconnected / connecting / connected / reconnecting）。
- 密文消息（发送给伴侣）；送达确认（ack）。
- 错误提示（配对码无效、协议不兼容、密钥校验失败）。

### 3.3 核心行为描述
1. **配对流程**：生成本地身份密钥对并持久化；生成含公钥与一次性随机数的 12 位配对短码；对方输入后完成公钥交换；双方各自派生共享秘密并分离出双向会话密钥；交换一次性验证码以校验无中间人。
2. **加密**：所有事件负载使用认证加密（XSalsa20-Poly1305）封装；中继仅可见目标标识、密文、过期时间，无法看到事件类型、发送方、明文。
3. **协议信封**：密文内包含协议版本、事件类型、发送方标识、单调递增序号、发送时间戳；传输层信封包含目标标识、密文、过期时间。

**事件类型注册表**（唯一登记处，上层模块仅可使用下表类型）：

| type | 方向 | 用途 | 所属模块 |
|------|:----:|------|---------|
| `hello` / `hello.ack` | 双向 | 连接握手与心跳 | 同步层 |
| `pairing.revoke` | 双向 | 解除配对（吊销密钥） | 同步层 |
| `msg.carry` | A→B | 带话内容 | 带话 |
| `carry.ack` | B→A | 带话送达确认 | 带话 |
| `carry.revoke` | A→B | 带话撤回（发送后 2 分钟内） | 带话 |
| `mood.sync` | 双向 | 情绪标签（valence/arousal/label） | 情绪同步 |
| `pet.feed` | 双向 | 养成积分增量（带签名） | 共同养成 |
| `pet.profile` | 双向 | 宠物名（改名时间戳） | 宠物档案 |
| `date.add` / `date.remind` | 双向 | 纪念日新增/修改、提醒庆祝 | 纪念日 |
| `date.sync` | 双向 | 每日零点对齐（共同登录天数/全量核对） | 数据一致性 |
| `gift.send` / `gift.accept` / `gift.expire` | 双向 | 礼物发送、接受解锁、过期退回 | 互赠 |

> 说明：`pairing.revoke`（配对吊销）与 `carry.revoke`（带话撤回）是两个独立事件类型，不可混用。

4. **传输**：局域网直连（mDNS 发现 + WebSocket 直连）为 M2 默认模式；中继模式（转发密文 + 离线暂存，TTL 7 天）预留接口，M3 再启用。
5. **连接状态机**：配对成功后进入未连接态；启动自动尝试连接；心跳每 30 秒一次，连续 3 次无响应判定离线并进入重连；离线期间事件进入本地发送队列。
6. **吊销配对**：任一方发起解除配对，发送 `pairing.revoke` 事件并本地清除会话密钥与伴侣信息；对方收到后同步清除；握手/重连时交换并校验配对版本号，任一端不一致即视为已吊销，提示重新配对（覆盖对方离线时 revoke 事件丢失的场景）。
7. **密钥存储**：私钥文件权限受限；会话密钥加密后落盘（Windows 用 DPAPI、Linux 用 SecretService；兜底为独立文件权限 600 并提示）。

### 3.4 业务规则与约束
- 协议版本不兼容时拒绝连接并提示升级。
- 事件序号单调递增；接收端按"发送方标识 + 序号"去重，重复事件丢弃。
- 未配对状态下禁止任何网络外发（默认单向关闭）。
- 离线事件入队后按序号升序补发；带过期时间的事件超时后标记失败。
- 连接失败自动重试，退避递增，不阻塞单机功能。
- 配对码有效期 **10 分钟**、重试上限 **5 次**；超限作废需重新生成；配对成功后码一次性消费作废。

## 4. 非功能需求

### 4.1 性能要求
- 同步线程空闲 CPU 占用 < 1%，内存 < 50MB。
- 局域网内端到端转发延迟 < 500ms。
- 加解密单事件耗时 < 10ms（KB 级负载）。

### 4.2 安全要求
- 端到端加密，中继无法解密；私钥永不出本机。
- 防重放（序号去重）、防篡改（认证加密）、防中间人（一次性验证码）。
- 会话密钥以密文落盘；吊销后密钥立即失效。

### 4.3 兼容性要求
- 支持 Windows 10/11 与 Linux（本项目 M2 以 Windows 为开发主线）。
- 协议与密码学选型需跨语言可互通（libsodium 兼容），为未来手机伴侣端预留。

## 5. 边界与限制

### 5.1 明确包含（In Scope）
- 配对码生成与交换、双向会话密钥派生、一次性验证。
- 事件加密、协议编解码、去重。
- 局域网直连（mDNS + WebSocket）。
- 中继客户端接口（连接、投递、离线拉取）——仅客户端侧。
- 离线发送队列与重试。
- 连接状态机与心跳。
- 密钥管理（生成、存储、吊销）。

### 5.2 明确排除（Out of Scope）
- 中继服务器实际部署与运维（M3 另行决策）。
- 手机伴侣端实现。
- 社交信任机制（如线下当面验证身份）。
- 消息内容审查或内容策略。

### 5.3 已知约束
- 配对需双方同时在线操作。
- 换机需重新走配对流程。
- 当前按"一人一端"假设设计，不支持一人的多设备同时在线。
- 公共中继模式下，中继不可信，一切数据必须以密文传输。

## 6. 验收标准（Acceptance Criteria）

- **Given** 两台未配对桌宠；**When** A 生成配对码，B 输入并确认；**Then** 双方显示"已连接"，后续发送的消息双方均可解密查看。
- **Given** 已配对且 B 离线；**When** A 发送一条带话；**Then** 事件进入本地队列，B 上线后自动补发，且 A 收到送达确认。
- **Given** 双方已连接；**When** 网络中断超过 3 次心跳周期；**Then** 状态转为重连中，期间发送的事件不丢失。
- **Given** 同一事件因网络重试被重复接收；**When** 接收端处理；**Then** 仅投递一次，其余丢弃。
- **Given** 中继存在且被抓包（**中继模式，M3 专属验收**；M2 以局域网直连抓包验证，协议同一套）；**When** 检查流量内容；**Then** 仅可见目标标识、密文、过期时间，无任何明文。
- **Given** 双方已配对；**When** 任一方发起解除配对；**Then** 双方本地密钥与伴侣信息被清除，后续消息无法收发。

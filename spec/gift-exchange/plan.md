# 互赠礼物 实施计划

> 关联 Spec：[[7-AI学习/11-AI桌宠情侣互联/spec/gift-exchange/spec.md|spec/gift-exchange]]
> 创建日期：2026-08-03
> 状态：已确认

## 1. 技术方案概述

互赠礼物是 M3 模块：情侣间虚拟礼物互赠，作为"郑重的表达"。核心链路：礼物库（manifest 加载 17 款 + 自定义彩蛋）→ 选择 → **二次确认** → `gift.send` 加密发送 → 本端乐观解锁（pending）→ 对方礼物盒弹窗 → 打开确认 → 校验解锁凭证签名 → 双方各自持久化解锁（`user_items`）→ `gift.accept` 回传 → 亲密度联动（+5 / 纪念日 +20）。发送记录持久化到 `gift_offers`，超 24h 未打开自动 `gift.expire` 退回可重发；解锁物品按 `expire_at` 到期失效。**发送后不可撤回**（与带话 2 分钟撤回规则不同）。

解锁一致性以"接受事件"为准（一次性、强一致，data-consistency 已定义）；亲密度加成走 pet-growth 积分入口（唯一来源表），纪念日特惠通过 anniversary 钩子判定。自定义彩蛋纯文本 ≤200 字、每端上限 20 个（超出替换）、不做语义审核、随 `gift.send` 端到端加密。

## 2. 技术决策

### 2.1 方案选型

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 礼物库来源 | `assets/manifest.json` 加载（17 款物品），程序不硬编码 | spec 已定；替换美术只覆盖 asset 文件 |
| 状态持久化 | `gift_offers`（发送记录：sent/accepted/expired）+ `user_items`（解锁物品 + expire_at + source） | spec 已定；data-consistency 已建表 |
| 赠送 | 二次确认 → `gift.send` 加密发送 → 本端乐观解锁（pending 记录） | spec 已定；先见效果，等待对方确认 |
| 打开确认 | 礼物盒弹窗 → 打开 → 校验解锁凭证签名 → 双方持久化解锁 → `gift.accept` 回传 | spec 已定；强一致以 accept 为准 |
| 过期退回 | 本地扫描 `gift_offers` 超 24h 未 accepted → `gift.expire` → 两端置 expired、发送方可重发 | spec 已定；与 data-consistency 事件清理衔接（礼物 expired 标记纳入清理） |
| 撤销限制 | 发送后不可撤回；仅确认前可取消 | spec 已定；与带话 2min 撤回不同，UI 明确提示 |
| 解锁一致性 | 以 `gift.accept` 事件为准（一次性、强一致） | data-consistency §3.3.6 已定 |
| 到期失效 | `user_items.expire_at` 每日检查，过期从可用列表移除 | spec 已定 |
| 亲密度联动 | 接受后双方各 +5（普通）/ 纪念日 +20 特惠（不与 ×2 叠加），走 pet-growth 积分入口 | spec 已定；数值基准 pet-growth 积分来源表 |
| 彩蛋 | 纯文本 ≤200 字、每端上限 20 个（超出替换旧的）、不做语义审核、随 `gift.send` 加密；确认后写入本端记忆库 | spec 已定；双人私密场景 |
| 离线兜底 | 离线时礼物事件经 data-consistency 离线队列暂存，恢复后补发；礼物在途暂待确认 | spec §5.3 已定 |

### 2.3 内部依赖

- **事件注册表**：`gift.send` / `gift.accept` / `gift.expire` 已在 sync-security 登记，本模块消费。
- **data-consistency**：`gift_offers` / `user_items` 表 schema 由 0001 基线定义；礼物 expired 状态变更时标记对应 events 行纳入清理（data-consistency prune 约定）。
- **pet-growth**：礼物接受积分通过其积分入口（`apply_intimacy_event`）合入；纪念日 +20 特惠判定复用 anniversary 钩子。
- **记忆系统**：彩蛋文本经主项目记忆库存储，本模块仅管理条目计数与上限（20 个/端）。
- **配置**：过期时长（24h）、彩蛋上限（20）、彩蛋长度（≤200 字）、到期检查触发（每日）。

## 5. 测试标准

### 5.1 单元测试标准

- **礼物库**：manifest 17 款加载；类型/稀有度/有效期字段；manifest 异常兜底。
- **状态机**：sent→accepted / sent→expired 合法流转；非法流转拒绝；同 giftId 幂等。
- **赠送**：二次确认后才发送；取消不产生记录；彩蛋 ≤200 字校验；重复点击不重发。
- **接收确认**：凭证签名校验；双方解锁一致；彩蛋 20 上限替换；"稍后"不阻塞。
- **过期退回**：24h 边界；两端状态一致；可重发；接收端清理弹窗。
- **到期失效**：`user_items.expire_at` 过期移除。
- **亲密度联动**：接受后双方各一次；+5 / +20 正确；纪念日不叠加；超上限拒绝。

### 5.2 集成 / 场景验证标准

- **前置条件**：sync-security、data-consistency、pet-growth 联调通过，双端配对在线。
- **步骤**：A 送"爱心气泡装扮" → B 弹窗 → B 打开 → 双方解锁 + 亲密度 +5 → A 再送一条不打开 → 模拟超 24h → 过期退回 → A 重发 → B 打开 → 纪念日场景 +20 → 互送彩蛋（超长被拒、20 上限替换）→ 解锁物品到期失效移除。
- **期望结果**：赠送、确认、解锁、过期、重发、联动、彩蛋全链路正确，双端状态一致，抓包仅见密文。
- **异常场景**：凭证伪造拒绝；超上限；离线暂存补发；取消不发送；彩蛋超限替换。

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 解锁凭证伪造 | 未授权解锁 | 凭证带签名校验（data-consistency 签名机制），失败拒绝解锁 |
| 24h 过期依赖本端计时 | 过期判定偏差 | 本地扫描 `sent_at` + 事件同步两端；与 data-consistency 事件清理衔接 |
| 离线时礼物在途 | 确认延迟 | 离线队列补发；礼物暂待确认；恢复后自动投递 |
| 乐观解锁与最终回退不一致 | 暂时多出物品 | 以 accept 事件为准（强一致）；过期时本端乐观解锁回退 |
| 彩蛋记忆库容量超限 | 记忆库膨胀 | 每端 20 上限、超出替换旧的；≤200 字约束 |
| 礼物素材缺失 | 展示异常 | 占位图兜底（08 排期 M3 内测前替换） |
| 发送后不可撤回造成误送 | 用户困扰 | 二次确认强调"郑重"语义；过期可退回重发兜底（spec 已定不可撤） |

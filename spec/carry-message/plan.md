# 带话功能 实施计划

> 关联 Spec：[[7-AI学习/11-AI桌宠情侣互联/spec/carry-message/spec.md|spec/carry-message]]
> 创建日期：2026-08-03
> 状态：已确认

## 1. 技术方案概述

带话功能构建在**已确认的同步层**（plan/sync-security）之上，作为第一个业务模块验证同步层接口。整体链路：用户语音/文字输入 → **规则意图检测**（M2 纯规则，未命中回普通对话）→ 正文抽取 → 发送前确认 → 加密发送 `msg.carry` → 对方解密 → 播报（弹窗 + TTS + 动画）→ 送达确认 `carry.ack` →（2 分钟内可撤回 `carry.revoke`）→ 24 小时过期失败。

核心是一个**带话状态机**（draft → sent → delivered / revoked / failed），`carries` 表持久化每条记录。M2 首版遵循两项决议：**纯规则意图检测、文本润色默认关闭**——不依赖分类模型与 LLM，先跑通"表达心意"的最小闭环。

## 2. 技术决策

### 2.1 方案选型

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 意图检测 | **触发词规则匹配**（关键词表 + 正则，如"告诉/帮我告诉/转告/跟 TA 说"），M2 纯规则 | spec 决议；规则未命中按普通对话处理 |
| 误报兜底 | 命中规则后仍需**发送前确认弹窗** | 用户确认天然过滤规则误报，无需模型 |
| 正文抽取 | 正则剥离前缀触发词 + 尾部语气词，不依赖 LLM | 纯本地、毫秒级；润色 M2 默认关闭（决议） |
| 状态持久化 | `carries` 表（spec 06 数据模型）存记录，状态字段流转 | 支持撤回窗口、过期扫描、发送端状态展示 |
| 送达确认 | 接收端点击"知道了"立即回 ack，或 **3 分钟自动 ack**；ack 幂等 | 自动确认延后至撤回窗口（2 分钟）之后，保证撤回窗口完整有效 |
| 撤回 | 发送 2 分钟内且对方未手动确认时可撤回（本地 `sent_at` 计时，超窗或已确认禁用按钮），发 `carry.revoke` 并同步清理"稍后看" | spec 已定；依赖双方在线 |
| 勿扰时段 | 配置每日勿扰时段，命中则静默收取进"稍后看"，不弹窗不朗读 | spec 已定 |
| 播报表情 | 按文本情绪匹配表情（复用主项目 EMOTION_MAP），兼容 07 动画状态机 | spec 已定 |
| 过期检查 | 本地定时扫描 `carries` 表，超 `expires_at`（默认 24h）未送达标记 failed | spec 已定；与 data-consistency 事件清理衔接 |

### 2.2 外部依赖

| 依赖 | 用途 | 新增 |
|------|------|:---:|
| 同步层（plan/sync-security） | `msg.carry` / `carry.ack` / `carry.revoke` 事件发送、接收回调、连接状态 | 已有（本模块首个使用者） |
| 主项目 ASR 管线 | 语音输入转文字 | 复用 |
| 主项目 TTS 管线 | 播报朗读 | 复用 |
| 主项目动画状态机 / 情绪系统 | 播报开口动画、表情匹配 | 复用 |
| 标准库 `re` | 规则匹配与正文抽取 | 无 |
| — | 分类模型 / LLM 润色 | **M2 不引入** |

### 2.3 内部依赖

- **事件注册表**：`msg.carry` / `carry.ack` / `carry.revoke` 已在 sync-security 注册（spec §3.3），本模块仅消费。
- **数据层**：`carries` 表 schema 由 data-consistency 定义；本模块提供记录的读写封装与状态流转。
- **配置**：勿扰时段、默认过期时长（24h）、撤回窗口（2min）、自动 ack 时长（3min）放入配置项。
- **UI 层**：发送确认弹窗、接收播报弹窗、状态展示（C 层 TODO）。

## 5. 测试标准

### 5.1 单元测试标准

- **意图检测**：触发词命中（前缀变体）；未命中普通闲聊；边界（句中触发词、尾部语气词、空正文）。
- **正文抽取**：各类触发词剥离正确；剥离后保留原文完整语义。
- **状态机**：draft→sent→delivered / revoked / failed 各合法路径；非法流转拒绝。
- **过期扫描**：24 小时边界（未到 / 恰到 / 已过）。
- **撤回**：2 分钟窗口内成功、超窗或已确认拒绝；窗口外 revoke 事件被接收端忽略。
- **ack 幂等**：重复 ack 不重复计、状态不回归。

### 5.2 集成 / 场景验证标准

- **前置条件**：sync-security 联调通过（plan/sync-security 验收完成），双端配对在线，TTS/动画主项目能力可用（可用文字弹窗降级验证）。
- **步骤**：A 输入"告诉 TA 今晚早点睡" → 确认弹窗 → 发送 → B 弹窗 + 朗读 → B 点"知道了" → A 显示"已转达"；再发一条 → 2 分钟内撤回 → B 端即时隐藏；断网发送 → 重连补发并自动确认；超 24 小时未送达 → 标记失败并提示。
- **期望结果**：全流程状态机正确，两端状态收敛一致，无重复播报。
- **异常场景**：普通闲聊不触发带话；勿扰时段静默入"稍后看"；重复 ack；窗口外撤回被忽略。

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 规则漏召回（无触发词的带话表达） | 当普通对话处理，功能不可达 | 确认弹窗兜底；M3 分类模型增强（spec 已排） |
| 规则误命中普通闲聊 | 误弹确认框 | 确认弹窗是"第二道闸"，用户取消即可，无实际发送 |
| TTS / 动画主项目能力未就绪 | 播报降级 | 弹窗文字展示兜底，朗读/动画失败不影响送达 |
| 撤回依赖双方在线 | 对方离线时撤回失败 | 2 分钟窗口提示网络状态；离线场景按 spec 允许延迟但过期失效 |
| 播报打断本地交互 | 打扰用户 | 勿扰时段 + 仅空闲播报（与 mood-sync 相同的低打扰原则） |
